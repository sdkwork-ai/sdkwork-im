# SDKWork IM Mini Program

Native WeChat mini program client for the SDKWork IM application (`sdkwork-im`).

- **Application key:** `sdkwork-im-mini-program`
- **Platform:** `MP_WEIXIN`
- **Client architecture:** `mini-program` (`MINI_PROGRAM_APP_ARCHITECTURE_SPEC.md`)
- **Domain / capability:** `communication` / `chat`

This root is one of five IM client roots. The PC root is the reference surface;
this root aligns to it through shared contracts, not through shared code.

## How it is composed

`src/` is the WeChat `miniprogramRoot`. It is a **bootstrap plus projection targets** — it holds no
business logic and no SDK client construction:

```
src/
  app.js                 platform entry: bootstrap -> restore session -> relaunch
  app.json               projection of the route contributions (regenerated by the build)
  app.wxss               global styles; restates the design tokens (asserted by a test)
  bootstrap/             composition root: host adapters, environment, clients, session, routes
  runtime/               generated: im-app.js bundle, runtime-env.js, build-manifest.json
  pages/                 main-package pages (login, inbox)
  package-chat/          `package-chat` subpackage (conversation, create-group)
```

`packages/` is the business architecture boundary — the `sdkwork-im-mp-*` package family:

| Package | Role | Owns |
|---|---|---|
| `sdkwork-im-mp-core` | `frontend-core` | composition root, SDK clients, session lifecycle, host contracts |
| `sdkwork-im-mp-commons` | `frontend-commons` | domain-neutral tokens, screen states, store, formatting, locale |
| `sdkwork-im-mp-shell` | `frontend-shell` | route placement/validation, tab bar, auth gate, session copy |
| `sdkwork-im-mp-host` | `frontend-host` | the **only** place that touches `wx.*` |
| `sdkwork-im-mp-chat` | `frontend-feature` | chat routes, services, stores, copy |

Platform pages and subpackages are packaging and loading boundaries only. `src/app.json` is
generated from the route contributions by `scripts/build-runtime.mjs`, so page placement has exactly
one source of truth.

## SDK integration

Three generated SDKs, all injected from the composition root:

- `@sdkwork/im-sdk` — IM app-api: inbox, message history, send, create conversation, realtime.
- `@sdkwork/im-app-sdk` — IM app-api surface wrapper.
- `@sdkwork/iam-app-sdk` — WeChat session exchange
  (`oauth.miniProgramSessions.create`), session validate/logout.

Three platform gaps have to be closed before a browser-shaped generated SDK can run in a mini
program, and all three live in `sdkwork-im-mp-host`:

1. no `fetch` — `installWeixinFetch()` maps `wx.request` onto a `Response`-shaped result;
2. no compatible `WebSocket` — `createWeixinSocketFactory()` adapts `wx.connectSocket` to the IM
   SDK's `ImWebSocketFactory` seam;
3. no session storage — `createWeixinSessionStorage()` adapts `wx.*StorageSync` to the injected
   `ImMpSessionStorage`.

## Runtime configuration

The ten profiles (`standalone|cloud` × `development|test|staging|demo|production`) are **generated**,
never hand-written:

```bash
# from the repository root
pnpm workflow:materialize-client-env            # regenerates all 40 client env files
node ../sdkwork-specs/tools/materialize-client-env.mjs --root . --check
```

They come from `etc/topology/<profile>.env` via the surface declaration in
`etc/client-env.materialization.json`. `scripts/build-runtime.mjs` selects exactly one profile and
fails when it does not declare the four identity keys.

## Commands

```bash
pnpm typecheck              # tsc over src/ and packages/
pnpm test                   # static contracts, config, route projection, env alignment
pnpm build:mini-program     # bundle + regenerate app.json (default: standalone.development)
pnpm build:mini-program:staging
pnpm build:mini-program:prod
```

Gates that also cover this root run from the repository root: `pnpm check`.

## Publishing

WeChat upload needs the WeChat DevTools CLI and a bound mini program appid. Both are operator-held
and absent from the workspace, so release packaging is deferred and recorded in
`sdkwork.app.config.json#artifacts.installConfig.metadata.releaseBuildDeferred`.
